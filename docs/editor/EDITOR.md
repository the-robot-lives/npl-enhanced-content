## 0. Vocabulary and scope

- **The model** is the one lossless XHTML document model (`src/editor/model/`). WYSIWYG
  and code view are both projections of it. It is the single source of truth for content.
- **The rendered DOM** is what the SemText elements build in light DOM. It is a
  *projection*: it contains runtime chrome the author never wrote (Lit's `<!---->` update
  markers, `.sem-note-summary` buttons, `.sem-facts-chrome`, sort buttons, snapshots).
  Runtime chrome is never model content; the serializer never emits it.
- **Authoring forms.** The vocabulary admits two spellings for everything: the element
  form (`<sem-fact>`) and the class alias (`.sem-fact`), plus the `data-*` attribute
  mirrors (`variant` ⇄ `data-variant`). Selectors in editor code use the shared helpers
  `sel(name)` / `part(name)` from `src/shared/sel.ts` — never a bare tag selector — so the
  editor edits both forms. Attributes: the editor edits the *authoring* spelling; the
  `data-*` mirror is the element's own afterParse write and is regenerated by
  `requestUpdate()` after every model-driven re-render (see §4.4).
- **Scope v1**: local-first editing of one XHTML document inside `<sem-editor>` (or any
  element subtree with `edit-mode`), code view, export/copy/autosave/VFS open+save.
  Out of scope v1: "Submit as proposal", collaborative editing, server persistence,
  CodeMirror (optional later lazy chunk), editing anything on the Next.js export.

Naming prefixes reserved by the editor: attributes `edit-mode`; data attributes
`data-sem-edit-*`, `data-sem-chrome`, `data-sem-inert`, `data-sem-editor-css`; events
`sem-edit-*`; CSS classes `sem-ed-*`; localStorage keys `semtext-editor:*`. No lane may
write into `themes/_vocabulary.css` and no lane may reuse a `.sem-*` class the vocabulary
already owns — editor chrome paints from `sem-ed-*` classes only (§9.3).

## 1. Architecture and bundle layout

```
                     ┌──────────────────────────────────────────────┐
                     │ <sem-editor> shell (src/editor/shell/)       │
                     │  titlebar (window-chrome) · toolbar · modes  │
                     │  outline · property modal · inserter · code  │
                     └──────────────┬───────────────────────────────┘
                                    │ owns one EditorContext
   ┌────────────────────────────────┼──────────────────────────────────┐
   ▼                    ▼                 ▼                    ▼
 model/               schema/           controller/          code/ + io/
 doc of record        elements.json     ReactiveController   projections
 (ops, history,       + descriptors     per edited element   + persistence
  selection)          (src/lit/*.edit.ts) + element chrome
```

- `semtext.js` (core bundle) grows by **≤ 0.5 KB raw**: the lazy edit-mode hook only
  (§4.1). It contains **zero** editor imports — static or dynamic at build time.
- `semtext-editor.js` (new `scripts/build.mjs` target): entry `src/editor/index.ts`,
  IIFE global `SemTextEditor`, budget **≤ 128 KB raw**, `es2022`. Everything in
  `src/editor/**` plus the per-element descriptors lives here. Loaded opt-in (§4.1);
  readers of ordinary SemText documents never download it.
- All editor DOM renders into **light DOM** (the edited elements are light-DOM hosts and
  the editor's chrome must be styled by the same theme channel). No shadow roots anywhere
  in the editor.
- The editor injects its own stylesheet once per document from a TS string
  (`src/editor/chrome-css.ts` → `<style data-sem-editor-css>`), so no lane edits
  `themes/` and CSS stays component-local (brief rule). The `<sem-editor>` frame reuses
  the existing `WINDOW_CHROME` class names for the frame itself (§5.1) — those paint via
  the existing `sem-browser` block of the vocabulary CSS which hosts already load; the
  editor stylesheet only fills editor-specific chrome.

## 2. Document model contract (`src/editor/model/`)

Published by LANE=model-core: `src/editor/model/types.ts` (first commit, @`0aaba35`).
Implementations live beside it (`parse.ts`, `serialize.ts`, `ops.ts`, `document.ts`,
`position.ts`, `entities.ts`) and re-export from `src/editor/model/index.ts`. §2 is
**types.ts restated for lane use**; the deltas found at reconciliation are listed in §13.
The model is pure data + pure functions over it: it never imports Lit and never touches
the DOM.

### 2.1 Node kinds and shapes

`EditorNode` is a discriminated union over `kind`; every node carries
`NodeCommon { id, parentId, range }`:

- `DocumentNode` (`kind: 'document'`) — the synthetic root; `parentId` is null only here.
- `ElementNode` — `name` (authored spelling, case-preserved; match with
  `name.toLowerCase()`), `attrs: AttrNode[]` in authored order, `children`,
  `selfClosing` (authored `<br />` form; void elements created by ops default to
  self-closing — `VOID_ELEMENTS`), plus the close-tag trivia the serializer needs
  (`preGt`, `closeTag`).
- `TextNode` — `value` (decoded; **edits write here**), `raw` (authored slice, emitted
  verbatim while `edited` is false), `edited` flag, and `mode: 'normal' | 'raw'`.
  `<script>`/`<style>` content is ONE raw text node (`RAW_TEXT_ELEMENTS`): entities not
  decoded, tags never parsed. This is what keeps the sem-chat JSON payload byte-exact
  and inert (§8).
- `CommentNode`, `CdataNode`, `ProcessingInstructionNode` (`target` + `value`),
  `DoctypeNode` — bodies verbatim, never decoded.

Attributes (`AttrNode`): `name` (matched case-insensitively), `value` (decoded; `null` =
bare/boolean attribute like `collapsed`), `rawValue` (authored slice with entities
intact; `null` once created/edited — the serializer then escapes `value`), `quote:
'"' | "'" | ''` (`''` = bare), `pre` (whitespace between the previous token and the
name), `range`.

Ids: assigned at parse time (`n1`, `n2`, …); never reassigned by edits; untouched nodes
keep their id across transactions. Op-created nodes allocate from the same document
counter via the factories `doc.createElement(spec)` / `doc.createText(value, mode?)`.
Ranges: half-open `[start, end)` in UTF-16 code units (`String.prototype.slice`
coordinates), valid as of the most recent `parse()`/`serialize()` — `serialize()`
refreshes every node's range and raw text (callers needing current offsets serialize
first). Trivia preserved per node: attribute order, quote style, per-attribute leading
whitespace, `preGt`/close-tag trivia, self-closing vs explicit close form, raw entity
text in text nodes and attribute values, comments, CDATA, PIs, doctype, inter-node
whitespace.

### 2.2 Parsing and the last-good tree

- Parsing lives **outside** the document. Module-level `parse(source)` /
  `tryParse(source)` return `ParseResult = { ok: true; doc: EditorDocument; issues } |
  { ok: false; doc; issues; error: ParseIssue }`. Neither throws; malformed input yields
  a best-effort tree plus structured `ParseIssue { code, severity, message, range }`s
  with typed codes (`unclosed-tag`, `mismatched-close`, `stray-close`, `unexpected-eof`,
  `invalid-char`, `bad-attr`, `unknown-entity`, `implicit-nesting`, `invalid-doctype`).
- The **last good tree** is a document-instance decision: the session keeps using the
  previous `EditorDocument` when `tryParse` returns `ok: false`; the code view renders
  the failed attempt's `issues` against the still-active tree. `doc.issues` carries the
  issues of the parse the instance was created from.
- Serialization: `doc.serialize(style?: Partial<SerializeStyle>)` — byte-identical for
  untouched nodes (`serialize(parse(x)) === x` is a property test over the whole corpus,
  §10); edited/created nodes re-emit canonically from preserved trivia plus
  `SerializeStyle { quote, indent, newline }` (`quote` affects newly created attributes
  only). `doc.serializeSubtree(id, style?)` emits one subtree and refreshes only its
  ranges — this is what the controller's re-render protocol uses (§4.4).

### 2.3 Ops

```ts
type EditOp =
  | { type: 'insertNode';     parent: NodeId; index: number; node: EditorNode }
  | { type: 'removeNode';     node: NodeId }
  | { type: 'moveNode';       node: NodeId; parent: NodeId; index: number }
  | { type: 'setAttr';        node: NodeId; name: string; value: string | null }
  | { type: 'removeAttr';     node: NodeId; name: string }
  | { type: 'setText';        node: NodeId; value: string }
  | { type: 'wrap';           node: NodeId; wrapper: ElementSpec }
  | { type: 'unwrap';         node: NodeId }
  | { type: 'replaceSubtree'; node: NodeId; replacement: EditorNode };

interface ElementSpec { tag: string; attrs?: Array<{ name: string; value?: string | null }>;
                        children?: EditorNode[] }
```

Semantics pinned for all lanes (guards enforced by `canApply(op)`; `apply` throws
`ModelError` on rejection — UI paths check `canApply` first):

- `index` is a position in the parent's `children` array **before** the op applies.
- `moveNode`/`insertNode` refuse to place a node inside its own subtree.
- `setText` targets text nodes only.
- Duplicate attribute names: `setAttr` rewrites the first match; `removeAttr` removes
  every match.
- Nodes passed by reference (`insertNode`, `replaceSubtree`'s replacement,
  `wrap`'s wrapper children) are **adopted** and must not already be attached to this
  document. Template snippets and duplicate subtrees therefore rebuild through
  `doc.createElement`/`doc.createText` so ids come from the document counter (§3.3).
- `setAttr` with `value: null` authors the bare attribute spelling (`collapsed`).
  Attribute position among the node's attrs is preserved; a surviving attribute keeps
  its authored quote, a new one follows `SerializeStyle.quote` (default `"`).
- `setText` writes decoded text; the serializer re-escapes (`escapeText`) on emit —
  callers never hand-escape into the model.
- `wrap` wraps **one** node in a new element (`wrapper`); wrapping a sibling run is one
  transaction — `wrap` on the first node, then `moveNode` each additional sibling into
  the wrapper. `unwrap` splices the node's children into its grandparent at its
  position and drops the element.
- Ops are the **only** mutation path. Descriptors and chrome never edit the DOM directly
  with intent to persist.

### 2.4 Transactions, history, events

- `doc.transaction(label, (tx) => { tx.push(op); … })` — ops apply immediately (the tree
  is live for reads inside the callback), batch into **one** undo entry and **one**
  change event; a rejected op rolls back the transaction's earlier ops (tree unchanged).
  `doc.apply(op, opts?)` is the one-op convenience. `doc.openTransaction(label)` returns
  a `TransactionSpan` (`commit()` / `abort()`, each exactly once) for async flows.
- Coalescing (typing): pass `TransactionOptions.coalesce` — transactions sharing a key
  merge into ONE undo entry while they arrive within the coalesce window. The inline
  text editor passes a per-node key (`text:<nodeId>`), so a typing burst is one undo
  step (§4.5). `silent: true` skips the change event (bulk imports).
- History: a single push-only stack for the whole document — `undo()` / `redo()` /
  `canUndo()` / `canRedo()` (**methods, not properties**), `history(): readonly
  HistoryEntry[]` (oldest first; `depth` counts from newest), `clearHistory()`.
- Events: `doc.on('change' | 'history' | '*', cb): Unsubscribe`. `ChangeEvent { doc,
  transaction, version }` fires once per commit; `HistoryChangeEvent { canUndo, canRedo
  }` on stack movement. `version` is monotonic, one bump per transaction commit; lanes
  use it to discard stale async re-renders (§4.4).
- The shell MAY mirror commits onto the `<sem-editor>` host as DOM CustomEvents
  (`sem-edit-change` / `sem-edit-selection` / `sem-edit-errors` / `sem-edit-mode`) for
  page embedders. The **intra-editor contract is `doc.on`** — no lane may depend on the
  DOM events existing.

### 2.5 Source-of-truth boundaries

- The **code view textarea** is an input device, not state: on each debounced re-parse the
  model re-installs the tree; WYSIWYG re-projects. The textarea holds the raw source of
  the *current* tree plus in-flight keystrokes.
- **Autosave/exports** serialise the model, never the DOM.
- The **`sem-source` element** inside an edited document snapshots authored markup at
  upgrade; after any edit that touches its host subtree, its descriptor's `rerender`
  re-runs the snapshot so the fence never shows stale source (§4.4, §3.4).

### 2.6 Selection and position mapping

- Model positions: `DocPos { node, offset }` — for a text node `offset` is a decoded-text
  offset (UTF-16 units of `value`); for an element it is a child boundary
  (`0..children.length`); for comment/cdata/pi it is an offset into the body.
  `Selection = { anchor: DocPos, focus: DocPos }`; equal for a collapsed caret.
- Source mapping lives on the document: `posToOffset(pos): number | null`,
  `offsetToPos(offset): DocPos | null` (rounds left), `rangeOf(id)`.
- DOM ⇄ model mapping — `caretFromDomPosition(domNode, domOffset): DocPos | null` and
  `domPositionFor(caret): { node: Text; offset: number } | null` — lives in
  `src/editor/controller/selection.ts`, deliberately outside `types.ts` (the model stays
  DOM-free). It walks **authored children only** (§0: runtime chrome and Lit `<!---->`
  markers are skipped); both return `null` for a position inside unmodeled chrome, and
  callers fall back to the nearest authored ancestor.
- WYSIWYG ⇄ code-view sync maps carets through `posToOffset`/`offsetToPos`. Split-mode
  selection sync is one-way-on-typing (the pane you type in drives; the other follows on
  commit or idle 250 ms) so the two never fight for focus.

## 3. Schema service and edit descriptors

### 3.1 Schema loading

`src/editor/schema/load-schema.ts` fetches/parses `elements.json` (same shape the repo
already ships: `{ specVersion, tags: [{ name, family, summary, description,
attributes[{name, required, type, allowedValues, default, description}], children[{name,
note}], example, optionsIn? }] }`). Notes the editor depends on:

- 49 tags today, `tagCount` is advisory — never hard-code it. Companion child tags
  (`sem-fact`, `sem-property`, `sem-detail`, `sem-view`, `sem-step`, `sem-event`,
  `sem-profile`, `sem-reference`, the `npl-*` parts) list their options via `optionsIn`
  pointing at the container tag.
- **`sem-chat` is not in `elements.json`** (it is an agent-kit element outside the
  normative schema). Its descriptor ships hand-written (§3.3, data bucket) and the
  validator treats it as schema-complete.
- `globalAttrNames = ['id', 'kind', 'tags']` (+ `audience` / `data-audience` dual-form)
  are appended to every tag's editable set, matching the global attribute catalog.

### 3.2 Descriptor files and registration

- One descriptor per element: `src/lit/<tag>.edit.ts` (SemText) and
  `src/lit/npl/<tag>.edit.ts` (NPL). Descriptor modules are **side-effect registering**:
  importing a module calls `registerDescriptor(d: EditDescriptor)` (from
  `src/editor/schema/registry.ts`).
- There is **no shared barrel** during Phases 1–2 (concurrent lanes would collide).
  Lanes test by importing their own descriptor module. `src/editor/index.ts` — owned by
  LANE=integrate in Phase 3 — carries the single import list that ships all descriptors.
- Coverage rule: every `elements.json` tag + `sem-chat` has a descriptor **or** inherits
  the auto-generated `attributesOnly` fallback (property modal from schema, context menu
  minus descriptor-only verbs, no text slots). The fallback makes a tag editable with
  zero authored descriptor; descriptors exist to *enrich*, not to enable. Coverage is
  asserted by a unit test enumerating the schema.

### 3.3 Descriptor shape

```ts
interface EditDescriptor {
  tag: string;                 // 'sem-note' — the canonical element spelling
  title: string;               // outline entry, label chip, inserter tile
  bucket: 'document' | 'prose' | 'disclosure' | 'views' | 'data' | 'sequence'
        | 'definitions' | 'recall' | 'code' | 'npl-a' | 'npl-b';
        // reference bucket (inserter grouping, Phase 2 lanes)
  summary?: string;            // schema summary default
  textSlots?: TextSlot[];      // §3.4
  itemList?: ItemListSpec;     // §3.4
  linkFields?: LinkField[];    // §3.4
  jsonItems?: JsonItemsSpec;   // sem-chat's <script type="application/json"> payload
  templates?: TemplateSnippet[];   // insert entries (inserter panel, slash menu)
  wizard?: WizardSpec;             // multi-step insert for complex elements
  regions?(el: SemElement): RegionMap | null;   // rendered node → model node id
  rerender?(el: SemElement): void;              // re-establish runtime chrome (§4.4)
  containerOf?: string;            // tag accepted as this element's item container
}

interface TextSlot      { selector: string; label: string; multiline?: boolean;
                          placeholder?: string; escape: 'entities' }   // v1: always entities
interface ItemListSpec  { childSelector: string; label: string;       // sel()/part() string
                          template: TemplateSnippet; max?: number }
interface LinkField     { attr?: string; slotSelector?: string; label: string }
interface JsonItemsSpec { selector: string; label: string;
                          schemaHint: string }          // shown in the JSON editor
interface TemplateSnippet { id: string; label: string; group?: string;
                          xml: string }   // XHTML with TextMate-style stops: ${1:text} ${2|a,b|}
interface WizardStep    { title: string; fields: WizardField[]; template: TemplateSnippet }
interface WizardField   { name: string; label: string; type: 'text' | 'url' | 'select' | 'textarea' |
                          'number' | 'boolean'; required?: boolean; options?: string[];
                          placeholder?: string }
type RegionMapEntry = { selector: string;
                        nodeId: NodeId | ((el: SemElement, index: number) => NodeId | null) };
type RegionMap = RegionMapEntry[];
```

Semantics pinned for all lanes:

- `textSlots[].selector` matches **authored child parts** (e.g. `sem-fact` slots:
  `part('statement')`, `part('conclusion')`, `part('incorrect-statement')`; `sem-note`:
  `:scope > .sem-note-body` *and* the body being the element's own unwrapped content —
  the descriptor declares both; the controller resolves at runtime). `:scope >` is
  mandatory in slot/list selectors.
- `itemList.childSelector` names the **repeatable child** (`:scope > sem-fact` for
  `sem-facts`, `:scope > table > tbody > tr` for `sem-table` via the table descriptor,
  `:scope > .npl-mood-tone, :scope > .npl-mood-context, :scope > .npl-mood-approach` for
  `npl-mood`). The `+`/`−` chrome (§4.6) stamps from this selector; `template` is the
  inserted item's snippet with the first stop focused.
- `templates[].xml` is the *authoring form* of an insert snippet. Stops use the
  `${n:placeholder}` / `${n|a,b}` grammar; the controller turns the first stop into the
  post-insert caret. Snippets are parsed with the module-level parser (never
  `insertAdjacentHTML`), then rebuilt through `doc.createElement`/`doc.createText` so
  ids come from the document counter and the adoption rule (§2.3) holds — safety passes
  apply to inserted content too.
- `regions()` maps what the element *rendered* back to model ids — needed wherever the
  element regroups or clones content (sem-note wraps the body in `.sem-note-body`;
  npl-mood groups details into `.npl-mood-detail`; sem-chat reuses authored
  `.sem-chat-msg` nodes). Entries are tried in order; the first hit wins; a miss falls
  back to index-of-authored-children.
- `rerender()` is the one-shot-wrapper seam. Thin wrappers that enhance once
  (`#wired` guard) would never re-enhance after the model replaces their children:
  `sem-table` → `enhanceTableElement(el)`, `sem-code` → `enhanceCodeElement(el)`,
  `sem-source` → its snapshot path. Elements whose `updated()` rebuilds chrome from
  presence guards (sem-note summary, sem-facts chrome, npl-mood panel) need no
  `rerender` — their `requestUpdate()` path handles it. Importing the `src/reading/*`
  enhance functions into the editor bundle is accepted (measured against the budget in
  §9.1; if over, the descriptors for those three move into a lazy sub-chunk — integrate
  decides on measurement, not speculation).

Pilot descriptors (Phase 1): `sem-note` (attributes + body text slot + collapsed toggle),
`sem-facts` (light-DOM item list of `sem-fact` with three text slots), `sem-table`
(item list of rows + `data-value` link-ish field + `rerender`). Phase 2 spreads one lane
per bucket (§11).

### 3.4 Field-to-op mapping (what each edit compiles to)

| Edit surface | Ops emitted |
|---|---|
| Inline text slot (contenteditable) | `setText` on the slot's text node (split/merge text nodes as needed) |
| Attribute field in property modal | `setAttr` / `removeAttr` per changed field, one transaction |
| `+` on an item list | `insertNode(parent, index, <item template rebuilt via createElement>)` |
| `−` on an item | `removeNode(item id)` |
| Link popover field | `setAttr(attr)` or `setText` (slot form), URL-safety-checked (§8) |
| Reorder (drag / Alt+arrows) | one `moveNode` |
| Wrap in… | `wrap(node, wrapper)` (+ `moveNode` per additional sibling) |
| Convert to… | `replaceSubtree` + `setAttr` mapping (per-descriptor convert table) |
| JSON items editor (sem-chat) | `setText` on the payload's raw text node (mode `raw` — byte-exact unless edited) |
| Insert before/after (menu, `+` zone, slash) | `insertNode` |
| Duplicate | `insertNode` of the subtree rebuilt via factories, sibling index + 1 — fresh ids |

## 4. Edit-mode controller (`src/editor/controller/`)

### 4.1 The base.ts lazy hook (owned by LANE=controller; contract here)

`src/lit/base.ts` gains **one private helper and two call sites**, ≤ 0.5 KB raw growth
including a new `src/lit/edit-hook.ts` module. Shape:

```ts
// src/lit/edit-hook.ts — entire module; the ONLY core-bundle editor code
const pending = new Set<SemElement>();
let loading = false;
export function queueEdit(el: SemElement): void {
  const api = (globalThis as any).SemTextEditor;
  if (api?.claim) { api.claim(el); return; }        // editor already loaded
  pending.add(el);
  if (loading) return;
  loading = true;
  const url = (globalThis as any).semtextEditorUrl
    ?? document.querySelector('script[data-sem-editor-src]')?.getAttribute('data-sem-editor-src')
    ?? new URL('./semtext-editor.js', import.meta.url).href;   // Vite rewrites; IIFE keeps fallbacks
  import(url).catch(() => { loading = false; /* silent: editing is opt-in */ });
}
export function drainPending(): Set<SemElement> { const p = pending; pending.clear(); return p; }
```

In `SemElement.connectedCallback()` (and after any `edit-mode` attribute flip the element
itself observes — a `static properties` entry is **not** added; the check is an attribute
presence test only):

```ts
if (this.hasAttribute('edit-mode') || this.closest('sem-editor[edit-mode]')) queueEdit(this);
```

Contract: core never *contains* editor code; the editor's entry installs
`globalThis.SemTextEditor.claim(el)`, drains `drainPending()`, and later arrivals attach
directly. Pages embedding the editor set `window.semtextEditorUrl` (or a
`data-sem-editor-src` script attr) when the bundle lives somewhere else. If the import
fails, elements simply render normally — no console throw, no retry loop.

`edit-mode` removal: the shell (and the shell-less claim path) observes `edit-mode`
attributes on its scope via MutationObserver, detaches controllers and strips
`data-sem-editing` chrome. base.ts does nothing on removal.

### 4.2 Attach/detach lifecycle

- `attachEditor(el: SemElement, ctx: EditorContext): EditController` — one controller per
  edited element; `ctx` is the shared `{ model, schema, descriptors, selection, shell? }`.
  `<sem-editor>` creates the context once and attaches controllers to every SemElement in
  its subtree (present and future — a MutationObserver on the shell covers late upgrades;
  `claim(el)` for shell-less mode builds a headless context around the element's own
  subtree).
- Attach stamps `data-sem-editing` on the element and wires the chrome (§4.3–4.7).
- Detach (edit-mode off, element disconnected, document closed): remove chrome nodes
  marked `data-sem-chrome`, release contenteditable, remove listeners, clear
  `data-sem-editing`. The model is untouched — detaching is not an edit.
- The controller is a Lit `ReactiveController` (`hostUpdate()` re-syncs outline flags) but
  never changes what the element renders: authored content is the element's own; all
  editor chrome lives in sibling nodes marked `data-sem-chrome`.

### 4.3 Hover outline and label chip

Hover (pointer) or focus-within (keyboard) draws the outline: a `sem-ed-outline`
`data-sem-chrome` sibling/overlay border + chip (`sem-ed-chip`) showing
`descriptor.title` and the tag spelling. The chip carries the drag handle (§5.6) and is
a `button` opening the property modal on Enter (keyboard parity for double-click's
"Edit…"). Chip text is `textContent`, never HTML. Reduced motion: outline transitions
gated per `reducedMotion()` from `src/shared/window-chrome.ts`.

### 4.4 The re-render protocol (light-DOM elements — the load-bearing section)

After a transaction touches element `E`'s subtree, the controller re-projects:

1. **Capture**: caret/focus if inside `E` (`caretFromDomPosition`), plus the set of
   `data-sem-chrome` nodes to drop.
2. **Replace authored children**: remove `E`'s current authored children — everything
   except `data-sem-chrome` nodes and comment markers — then insert the model's children
   of `E` as a fragment built by `renderAuthorInert()` (§8): the source emitted by
   `doc.serializeSubtree(E)` is re-parsed and stamped via `createContextualFragment` so
   scripts
   are neutralised on the way in. Preserving untouched subtrees *node-for-node* (moving
   existing DOM instead of re-creating) is the v1 optimisation: children whose model ids
   still exist with unchanged ranges are kept and re-ordered, not rebuilt — this keeps
   media elements from reloading and text carets stable.
3. **Re-establish chrome**: `el.requestUpdate()`; await `el.updateComplete`; the
   element's own `updated()` rebuilds presence-guarded chrome (sem-note summary,
   sem-facts chrome, npl-mood detail panel). Then `descriptor.rerender?.(el)` for
   one-shot wrappers. Anything still pending children resolves through
   `el.whenChildrenReady(selector)` — the controller awaits the same promise the element
   uses rather than polling.
4. **Restore**: re-apply the captured caret; if the focused chrome was rebuilt, refocus
   its successor. Emit nothing (the document already fired its `change` event via
   `doc.on`; the re-render is a projection, not an edit).
5. **Guard every step on `version`**: a newer transaction invalidates an in-flight
   re-render; the newest one wins.

Lit's `<!---->` markers: created by Lit's light-DOM render, they are stripped from the
model on parse (same rule `sem-source` applies) and never round-trip into serialization.

### 4.5 Inline text editing

- Double-click (pointer) or Enter on a selected text slot (keyboard) turns the slot into
  `contenteditable="plaintext-only"` (`contenteditable="true"` fallback where
  unsupported, with paste forced through the sanitizer). One text node per slot while
  editing; the slot keeps its authored wrapping.
- **Enter** inserts a line break (multiline slots) or commits (single-line slots).
  **Blur** commits. **Esc** reverts to the model value without an op. Commit = one
  `setText` transaction (decoded value committed; the model re-escapes on emit —
  `TextSlot.escape` stays `'entities'` for paste paths), announced via `aria-live`
  (§7).
- Typing coalesces in history (§2.4). The editor never re-renders under an active
  contenteditable caret — model changes from elsewhere defer that slot's projection until
  blur.

### 4.6 `+` / `−` item glyphs

Stamped from `descriptor.itemList`: a `−` chip on each matched item (hover/focus) and a
`+` chip after the last item. Both are real `<button type="button">` elements with
`aria-label` ("Remove item 3 of 5" / "Add <label>"), `data-sem-chrome`-marked, excluded
from serialization by that marker. They emit exactly the §3.4 ops. Keyboard: the item
itself is focusable; Alt+Delete removes the focused item, Alt+= inserts after it (§7
table).

### 4.7 Context menu (reuse of `ContextMenuController`)

The terminal menu is generic enough to host editor verbs, but `open()` builds items via
the terminal-specific `buildMenuItems(host)`. Contract for the additive change (made by
LANE=controller in Phase 1; terminal behaviour byte-identical; the existing terminal menu
tests stay green):

- `ContextMenuOptions` gains `items?: (host: MenuHost) => readonly MenuItemSpec[]`
  (default `buildMenuItems`).
- `MenuItemSpec.id` widens from the closed terminal union to `string` (terminal ids and
  their e2e hooks unchanged).

The editor supplies `EditorMenuHost` implementing `MenuHost` with no-op/false terminal
verbs (copy/paste delegate to the browser default; `findAvailable()/canvasAvailable()`
false; `armBrowserPassthrough()` honouring Shift+right-click passthrough unchanged) and
builds its items:

`Properties…` · `Edit` (slot jump) · `Duplicate` · `Move up` · `Move down` ·
`Wrap in…` ▸ (container picker) · `Convert to…` ▸ (per-descriptor targets) ·
`Insert before…` · `Insert after…` · `Delete` — item ids
`properties, edit, duplicate, move-up, move-down, wrap-in, convert-to, insert-before,
insert-after, delete`. Disabled-with-hint follows the existing pattern (e.g. `Convert to…`
disabled with `no conversions` when the descriptor declares none). The menu opens on
right-click, Shift+F10 / ContextMenu key, and long-press via the controller's built-in
paths; the anchor element's `surface()` is the edited element. A11y is the controller's
own (roving focus, Escape-close-and-refocus, `aria-haspopup`).

### 4.8 Shell-less mode

`edit-mode` on an element outside any `<sem-editor>`: the hook loads the bundle;
`SemTextEditor.claim(el)` builds a headless context (model from the element's
serialized authored subtree — the *document* is still the unit of serialization for
export; the claim only scopes selection and re-render). Element chrome works identically;
shell UI (outline, toolbar, code view) is absent. This mode is secondary; e2e covers it
with one smoke test.

## 5. Editor shell — `<sem-editor>` (`src/editor/shell/`)

### 5.1 Frame

`<sem-editor>` is itself a `SemElement` (light DOM, registered via
`SemElement.register`). Its frame adopts `src/shared/window-chrome.ts`:

- `createWindowTitlebar({ title, tone, actions })` rendered imperatively as first child —
  sem-editor owns its children (the document moves into the viewport), the same altitude
  as sem-browser. `title` = document name (`<title>`, else filename, else "Untitled").
- Content region gets class `sem-window-viewport` (the scrollable, focusable region).
- Frame element: `sem-window`; `size`/`data-size` presets behave as documented there.
- The editor's toolbar is the second row (not window-chrome actions — those keep host
  controls): Undo · Redo · mode toggle (segmented `WYSIWYG | Code | Split`,
  `role="radiogroup"`) · Insert ▸ · Export ▸ · Open ▸. Toolbar buttons carry
  `aria-keyshortcuts` and tooltips via `title` + `aria-label`.

### 5.2 Modes

- `wysiwyg` (default): canvas only. `code`: source only. `split`: side-by-side ≥ 900 px,
  stacked below (container query, not viewport — the editor is embeddable).
- Mode is reflected as `data-mode` on `<sem-editor>`; `sem-edit-mode` announces it.
  Split shares one model; both panes project it; §2.6 pins selection arbitration.
- Document content source: children authored inside `<sem-editor>` (move-on-connect into
  the model — the element's light-DOM children are parsed once on attach and re-projected;
  the authored source is preserved byte-for-byte by the model, not by leaving the
  original nodes in place), or `src`/`<script type="application/xhtml">`-style sources
  are v1-out (the `/editor` page loads documents via IO instead).

### 5.3 Outline and breadcrumb

- Outline pane (left rail, collapsible, hidden < 700 px): tree from `doc` ancestor walks
  (`ancestorsOf`) of
  element nodes with descriptors (`title` + tag), keyboard-navigable listbox; Enter
  selects + scrolls into view; F2 / Enter-again opens properties; Delete removes with the
  §7 confirm path. Current selection follows the canvas.
- Breadcrumb row above the canvas: `ancestorsOf(selection)` as `nav[aria-label="Breadcrumb"]`
  links; clicking an ancestor selects it.

### 5.4 Property modal

- `<dialog>` (native, `showModal()`) titled `Properties — <descriptor.title>`.
- Fields: every schema attribute (plus global catalog) → widget by `type`:
  `string`→text input, `boolean`→checkbox, `integer|number`→number input,
  `allowedValues.length > 0`→`<select>` listing the enum **plus** the current value if
  non-enum (marked "(custom)") so hand-authored values are visible, not destroyed.
  Required fields marked; missing required shows inline warning text (warn-not-block per
  plan). Unknown-on-node attributes land in an "Advanced" section with remove buttons.
- Sub-item list editor (for `itemList` descriptors): rows = items (`label` + first text
  slot preview), reorder via Alt+↑/↓ or drag, add (template), remove — each row action is
  the corresponding op; the dialog applies **one transaction on Save**, no live edits
  behind a modal. Cancel/Esc = no ops.
- JSON items (sem-chat `jsonItems`): `<textarea spellcheck="false">` with live JSON
  validation (error line + message under the field) and the payload type fixed to
  `application/json` — the only script node the editor will author (§8).
- A11y: focus trap + restore, roving order, `aria-live` announce on save
  ("Updated 3 attributes on sem-note"), Esc = cancel everywhere, Enter in a field moves
  through fields (not submit) to prevent accidental commits on long forms.

### 5.5 Insert

Four roads, one op:

1. **`+` between blocks**: hovering the gap between element-level children reveals a
   `+` button (`data-sem-chrome`); click opens the block inserter popover scoped to
   containers the schema permits at that position.
2. **`/` slash**: typing `/` at the start of an empty text slot opens a filterable
   template menu (arrows + Enter); Esc dismisses; a `/` typed with any preceding text is
   literal.
3. **Block inserter panel** (toolbar `Insert ▸`): grouped by `bucket`, tiles show
   `title` + summary; filter box on top.
4. **Wizard**: descriptors with `wizard` run the stepped modal instead of dropping a
   template (steps render `WizardField`s; Back/Next preserve entries; Finish compiles
   `steps[].template` into one snippet → parse → `insertNode`). Complex elements
   (`sem-table`, `sem-facts`, `sem-chronology`, `npl-poa`, …) ship wizards in Phase 2;
   elements without one fall back to templates + the property modal.

Schema-permitted placement: insert targets are validated against the schema
(`children`/`optionsIn` data) and the descriptor list; disallowed insert points never
render a `+`.

### 5.6 Drag and drop + keyboard moves

- Drag handle = the label chip (§4.3). HTML5 DnD; `dataTransfer` carries the node id
  (`application/x-sem-node`) — **never HTML** (paste/drop of raw content goes through the
  sanitizer path, §8). Drop indicators render only placements the schema permits (valid
  sibling index or valid container). Esc cancels a drag; drop = `moveNode`.
- Keyboard equivalents (roving over outline or canvas selection):
  - `Alt+↑` / `Alt+↓` — move within parent (`moveNode`, index ± 1).
  - `Alt+Shift+↑` / `Alt+Shift+↓` (or ←/→) — promote/demote: demote moves the node into
    its previous sibling when that sibling's descriptor/schema accepts children;
    promote splices it out to the grandparent. Invalid moves are no-ops with an
    `aria-live` announcement ("cannot nest sem-property outside sem-properties").
- Every DnD affordance is a keyboard action first: the pointer paths are conveniences,
  and §7's parity table is tested.

## 6. Code view (`src/editor/code/`)

- Structure: a stack — `<pre class="sem-ed-code" aria-hidden="true">` highlight layer
  under a transparent-text `<textarea>` (the editor of record). Both scroll together
  (single scroll container; textarea sized to content). `wrap` toggles
  `white-space: pre-wrap` on both layers.
- Highlighter: `src/editor/code/highlight.ts` adapts the HTML scan from
  `src/terminal/sh-highlight.ts` (`highlightHtmlLine` / `findTagEnd` / `highlightTag`) to
  emit **spans** (not SGR): token kinds `tag`, `attr`, `value`, `comment`, `doctype`,
  `entity`, `text` as `sem-ed-tok-*` classes. Line-by-line scan over
  `source.split('\n')` — same streaming discipline as the terminal scanner; the model's
  `ParseError` ranges overlay as gutter markers + squiggles (`sem-ed-err`), listed in a
  `role="alert"` strip under the toolbar with jump-to-line links.
- Live re-parse: `input` → debounce 300 ms → `tryParse` → clean: adopt the new
  document and re-project; errors: keep **last good tree** active (§2.2), show the error strip, mark the
  textarea `aria-invalid="true"`. Fixing the source auto-recovers; the manual "Re-parse
  now" button is the escape hatch for pasted-large-source jank.
- Tab key inserts two spaces (source editing), never leaves the textarea.
- Selection sync: §2.6. No CodeMirror in v1 (budget §9.1).

## 7. Accessibility

- **Keyboard parity** (tested; every row has an e2e): double-click-edit ⇄ Enter/F2 on
  selection; right-click menu ⇄ Shift+F10; drag-move ⇄ Alt+arrows (§5.6); `+`/`−` ⇄
  Alt+=/Alt+Delete; modal open/close ⇄ Enter/Esc; mode toggle ⇄ Cmd/Ctrl+Shift+E cycles;
  undo/redo ⇄ Cmd/Ctrl+Z / Cmd/Ctrl+Shift+Z; save(export) ⇄ Cmd/Ctrl+S; outline focus ⇄
  Cmd/Ctrl+Shift+O; code view ⇄ Cmd/Ctrl+Shift+C.
- **Focus**: roving tabindex in menu (controller's own), outline listbox, toolbar
  (toolbar = one tab stop, arrows inside), modal fields; focus restored to the invoker on
  close; `:focus-visible` styles from the editor stylesheet; the frame reuses
  `sem-window`'s `:focus-within` convention.
- **Announcements**: one `aria-live="polite"` region per editor (`sem-ed-live`) fed by a
  single `announce(msg)` helper — commits ("Renamed attribute…"), moves, deletions, insert
  results, parse error counts. Destructive actions (Delete of a subtree with > 1 node)
  require confirm-or-undo: the announce names the undo path ("Deleted sem-facts (3 items).
  Cmd+Z to undo."), no blocking confirm dialogs except model-emptying actions.
- **Motion**: all editor transitions gate on `reducedMotion()`; drag indicators and
  outlines are opacity/border only.
- **Semantics**: editor chrome is `aria-hidden`/buttons with labels — never part of the
  document outline; the canvas keeps the document's own semantics (no `role="textbox"`
  on the canvas; individual slots become textboxes while editing).
- Reduced-transparency / forced-colors: chips carry text labels, never colour alone.

## 8. Safety

- **The model never executes.** `renderAuthorInert()` is the only path from source to
  preview DOM: it parses, drops nothing from the model, but neutralises in DOM —
  `<script>` nodes become placeholders (`<template data-sem-inert data-sem-script-type="…">`
  preserving the original `type` and body) so serialization round-trips byte-exact while
  nothing executes. The single exception the editor *authors* is
  `<script type="application/json">` (sem-chat fixtures) — inert by type. No
  `srcdoc`, no `<iframe>` insertion, no `javascript:` anywhere.
- **URL fields** (link popover, `url` wizard fields, attribute text inputs on URL-ish
  attributes — `href`, `src`, `endpoint`, `fixtures`): values must be empty, `#…`,
  same-document, `http(s):`, `mailto:`, or relative; anything else (incl. `javascript:`,
  `data:` except `data:image/*` for `src`) is rejected inline with a message, never
  written. The rule lives in `src/editor/safety/url.ts` with its own unit tests.
- **Paste / drop sanitising**: `src/editor/safety/sanitize.ts` — parse the pasted HTML,
  keep only: known SemText tags (schema names + class-alias forms), basic formatting
  (`p, br, strong, em, b, i, ul, ol, li, a, code, pre, blockquote, h1–h6, table, thead,
  tbody, tr, th, td, caption`), global-catalog attributes plus `href/src/alt/colspan/
  rowspan/scope/data-value`. Everything else (event-handler attrs, `style`, unknown
  tags) is dropped and the drop summary announces. Sanitised output re-parses through the
  model before insertion — no `insertAdjacentHTML` anywhere in the editor.
- **Serialization fidelity vs safety**: safety filters *rendering and insertion*, never
  the model — a document authored (by hand) with a `<script>` round-trips untouched in
  code view and export; the editor simply never executes it and flags it in the outline
  with a warning chip.

## 12. Persistence & IO summary (`src/editor/io/`)

- `exportDocument(model): string` — full-document serialization; fragment edits export as
  a full document with an HTML comment marker naming the fragment root.
- Copy: `text/plain` serialization to the clipboard (the §7.4-style ladder: try async
  clipboard, fall back to a hidden textarea + `execCommand('copy')`).
- Autosave: debounced (1 s) post-change write to `localStorage['semtext-editor:draft:<key>']`
  (`{ source, savedAt, mode }`); drafts list on Open (`semtext-editor:drafts` index);
  restore loads source through `parse` (errors surface like any import); delete is
  undoable only within the session (localStorage has no history).
- VFS: `EditorStore` interface `{ read(path): Promise<string>; write(path, source): Promise<void>;
  list(dir?): Promise<FileInfo[]>; delete(path): Promise<void> }` implemented over the
  existing backends in `src/terminal/backends/**` (memory, localStorage, S3). Open/Save
  dialogs are the shell's; no backend is contacted unless the user picks one (local-first).
