The deck

The landing page's four facts as one document — one source, three renderings.

view-as is a parameter, not an identity. The same facts render as cards, prose, or a table without rewriting the document. Each view needs its own hand-maintained copy of the content. Components render into light DOM. Reader styles, extensions, and print see the real elements. Web components require Shadow DOM encapsulation to work. Extraction reads the authored document. What you wrote is what the CLI outputs contain. A separate pipeline re-parses the page into structured data. Authoring needs no build step. Drop an .html file in the set and every view already serves it. New content must pass through a bundler before it is readable.
