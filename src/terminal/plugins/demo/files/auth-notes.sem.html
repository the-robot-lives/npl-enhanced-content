Auth notes

Working notes on issuing and rotating the access/refresh pair — the sections demo outline, toc, and the records view.

Issuing tokens

Sign-in returns two tokens with different jobs and lifetimes.

Short-lived; travels on every request. Long-lived; used once at the issuer to mint the next pair. Refresh token server-side by family; access token in memory only.

Access tokens

Stateless and audited by claim, not by lookup. Expiry is the whole security story, so it is measured in minutes.

Refresh tokens

The only credential allowed to speak to the issuer after sign-in. Single-use and rotated.

Rotating the pair

Redeem the refresh token, mark it consumed, issue the next pair. A replayed token means a stolen family — revoke the whole family.

client                  issuer
  |  -- refresh -->      |
  |                      |  mark old token consumed
  |  <-- new pair --     |
  |                       |
  |  -- old refresh -->  |  replay! revoke family
