# SemText extension — M2 (raw path)

Chrome (MV3) extension rendering SemText `.html` documents from GitHub raw
views. Design: `docs/viewer-and-extension.md` (branch `feat/semtext-viewer-design`,
commit 404ed57) — milestone M2 = "Render banner on raw `.html` → viewer tab →
public raw fetch → jail render".

## Layout

- `manifest.json` — MV3. Content script on `raw.githubusercontent.com` only;
  host permission for raw only; `permissions: ["storage"]`; `jail.html` under
  `sandbox.pages` (no `chrome.*` in the jail). No WAR / options / github.com
  host — those land with M3 (blob auto-render + cookie-authenticated fetch).
- `content.js` — Render banner on raw `.html`/`.htm`/`.xhtml` views. Holds no
  document text; the click asks the service worker to open the viewer tab.
- `background.js` — typed URL guard (`lib/raw-url.mjs`, unit-tested) then
  `chrome.tabs.create('viewer.html#<encoded-raw-url>')` (hash, not query).
- `viewer.html` + `viewer.js` — boot-loader tab: hash → shared boot chain
  (fetch raw with credentials omitted, 10 MB cap, allowlist re-check after
  redirects, typed errors — design D3/T3). Consent "always allow" persists in
  `chrome.storage.sync` (design D2); the hosted viewer uses localStorage.
- `jail.html` — the render jail, Chrome-sandboxed (opaque origin, own CSP,
  no extension APIs). Same jail code and trusted bundle as the hosted viewer.
- `vendor/` — NOT committed. Regenerated by `scripts/build-extension.mjs`
  from `viewer/*.mjs` + the Lit bundle (`dist/semtext.js` from the
  `feat/lit-only-bundle` build). Never hand-edit.

## Local run (unpacked)

```sh
node scripts/build-extension.mjs     # assemble extension/vendor/
# Chrome → chrome://extensions → Developer mode → Load unpacked → extension/
```

Then open any public raw `.html` file, e.g.
`https://raw.githubusercontent.com/h5bp/html5-boilerplate/master/dist/index.html`,
and click **Render with SemText**. (M2 is public-raw only; private repos are
M3 and deliberately produce a typed refusal today.)

## Tests

- Unit: `npx vitest run test/unit/extension-raw-url.test.mjs test/unit/extension-manifest.test.mjs`
  (guard, heuristic, hash parsing, manifest envelope, vendor presence).
- Browser canary (real Chrome for Testing with the extension loaded; no
  local server, nothing to stop): `npm run test:extension`
  (`test/e2e/extension-raw-banner.mjs` — asserts the banner injects on a
  real raw .html view and stays quiet on .md; set `CFT_BIN` to point at
  your Chrome for Testing binary).

  Why not Cypress: branded Chrome ≥ 137 refuses `--load-extension`, and
  Cypress's launcher did not carry the flag to Chrome for Testing either
  (measured 2026-10-13), so the extension canary drives CfT directly.

  Cypress cannot follow the new tab the button opens in any case, so the
  click → viewer tab → jail leg is covered by the unit suite (guard, hash
  parsing, vendored boot chain; the jail itself is M1-proven) and the
  manual load above.
