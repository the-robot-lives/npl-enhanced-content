sem-bind — live data on sem-* elements

One hydration pipe for every source: a plain URL — a full https://… address or a same-origin relative path like ./data/… resolved against this page (static JSON, no auth) — an agent-kit/… shorthand (the agentonomi status routes, bearer-token auth with popup login on 401), or a direct payload property (no server at all — demos and tests). Token lives in localStorage["semtext.bind.token"], per origin, never a cookie.

A bound element attaches once: later sem-bind attribute changes are ignored by the attach guard — reload the page to repoint a bind.

Static JSON — percent progress

./data/progress-percent.json → {percent, comment}. Progress binds poll (30s default); this one is tightened to 15s via sem-refresh="15" so the refetch is visible in devtools.

{ "percent": 42, "comment": "scouting repos" }

Static JSON — step / steps progress

The fraction form: {step: 3, steps: 7, comment} renders the same meter at step/steps with a step 3 / 7 caption.

Plan from a KV definition — the agentonomi {definition, status} shape

./data/plan-definition.json carries no plan markup at all — just a definition object whose steps array (strings or {id|key, label|title}) plus the per-step status dictionary. This is exactly what GET /status/…/plan/{id} returns from a fully KV-defined record. The element below has no authored children, so hydration generates the step list from the definition and the dictionary annotates it like any authored record; authored children would win if present. With JavaScript off this one stays empty — the definition only exists in the fixture.

{ "definition": { "steps": [ {"id": "kv", "label": "…"}, … ] },

Auth flow

On a 401 from any host the runtime opens https://agentonomi.com/embed/authorize?redirect_uri=…&state=… in a popup; the embed posts {type: "semtext-bind-token", access_token, expires_in, state} back and closes. Popup blocked → full-page redirect; the token returns in the #access_token=… fragment and is verified, stored and stripped on the next load.
